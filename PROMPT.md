# Роль

Ты работаешь как ИИ-агент внутри учебного проекта. Собери цельную
одностраничную рекламную веб-страницу из материалов, которые подготовил
студент. Сохраняй авторские решения проекта и не подменяй их универсальным
шаблоном.

# Перед сборкой

1. Прочитай README.md.
2. Полностью прочитай research.md, era.md, concept.md и sources.md.
3. Найди все Markdown-файлы в blocks/ и прочитай их по порядку числовых
   префиксов.
4. Просмотри доступные материалы в assets/.
5. Кратко сформулируй:
   - какой объект и какую эпоху представляет проект;
   - кому адресован курс и что он обещает;
   - какие блоки войдут в страницу и в каком порядке;
   - какие конкретные правила из era.md нужно соблюдать.
   После этого переходи к сборке.

# Источники истины

- `research.md` — исторические факты и ценность объекта;
- `era.md` — временной диапазон, технологическая среда, визуальный язык,
  рекламный язык, границы стилизации;
- `concept.md` — аудитория, обещание, голос, центральная шутка;
- `blocks/*.md` — набор, порядок, содержание и назначение секций;
- `sources.md` — подтверждённые факты и визуальные ориентиры;
- `assets/` — локальные материалы.
Не меняй эти Markdown-файлы без отдельной команды студента.

# Главная задача

Создай готовый `index.html`. Страница рекламирует вымышленные курсы по объекту
исследования так, как это могло бы выглядеть в выбранную эпоху. По странице
должно быть видно, что историческая ценность языка понята, а адрес курса и
его характер времени — воспроизведены.

# Содержание

Используй `blocks/*.md` как структуру страницы. Сохраняй порядок файлов. Не
добавляй новые смысловые секции только ради приличия. Если видишь проблему в
наборе блоков — кратко сообщи о ней, затем собери страницу по существующим
блокам.

Можно редактировать формулировки, ритм и вёрстку внутри этих решений. Смысл
проверенных фактов менять нельзя. Не придумывай даты, цитаты, рейтинги и
исторические события. Если рекламного факта нет в подготовленных материалах,
оставь нейтральную формулировку или сообщи студенту о проблеме.

Список фактов, которые нельзя искажать: даты 1.0 и 1.31.0, формулировки
обещания стабильности, цикл релизов раз в шесть недель, цифры 1400/5000,
33 → 74 организации, версия 1.17.0 от 27 апреля 2017, слоган «без segfault'ов»,
девять «Возможностей» 2017 года.

# Визуальная система

Опирайся на era.md и визуальные источники из sources.md. Используй
характерные для периода типографику, плотность, рамки и приёмы. Все секции
должны ощущаться частью одной рекламной истории, а не подборкой разных
шаблонов. Избегай решений, которые перечислены в разделе «Границы
стилизации»: огромных скруглений, стекла и размытия, тёмной темы с
переключателем, градиентных mesh-подложек, emoji вместо иконок, скруглённых
«наклеек», фотобанка, современной типографики в духе 2020-х, киберпанка.
Хомор должен подчёркивать историческую ценность и реалистичность эпохи.

# Технический результат

- один файл `index.html`;
- страница открывается локально без сервера и сборки;
- CSS может размещаться внутри HTML;
- JavaScript используется только там, где он действительно нужен, где
  поддерживается задумкой;
- локальные изображения подключены относительными путями из `assets/`;
- внешние библиотеки и сетевые зависимости не нужны;
- текст остаётся читаемым на обычном экране ноутбука;
- никакие элементы не перекрывают основное содержание.

# Самопроверка после сборки

Сопоставь `index.html` с research.md, era.md, concept.md и каждым файлом
`blocks/*.md`. Проверь, что:
- исследование честно отражено понятным языком;
- выбранная эпоха узнаваема по нескольким согласованным признакам;
- каждый подготовленный блок присутствует и выполняет свою задачу;
- тексты не содержат выдуманных исторических утверждений;
- визуальная система поддерживает одну рекламную историю;
- `index.html` открывается локально.
Исправь обнаруженные технические ошибки. Концептуальные решения студента
сохраняй.
